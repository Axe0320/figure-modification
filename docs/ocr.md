# Phase 6 OCR パイプライン

## 概要

アップロードされた PNG を解析してデータを復元し、編集可能な FigureState に変換する。
OCR だけでは軸・棒・線・色は復元できないため、処理を明確に分離する。

---

## パイプライン

```
PNG アップロード
    ↓
【前処理】Canvas API（ブラウザ）
    - リサイズ（max 1280px）
    - コントラスト調整
    ↓
【文字抽出 / 構造解析】
    ┌─────────────────────┬──────────────────────────────────────┐
    │ APIキーなし          │ APIキーあり                           │
    │ Tesseract.js         │ Vision LLM                            │
    │ （ブラウザ）         │ Claude / GPT-4o / Gemini 2.0 Flash   │
    └─────────────────────┴──────────────────────────────────────┘
    ↓
【ユーザー確認・修正】
    - 抽出結果を表示
    - ユーザーが確認・修正
    ↓
FigureState
```

---

## 各ステップの詳細

### 前処理（Canvas API）

Pillow（Python）は Vercel の Python 3.12 環境でのバージョン制約から除去し、
全前処理をブラウザ側の Canvas API に移行した。

- リサイズ（max 1280px）: `canvas.drawImage` による縮小
- コントラスト調整: `ctx.filter = 'contrast(1.2)'`

### 文字抽出 / 構造解析

| 条件 | 処理 | 説明 |
|---|---|---|
| APIキーなし | Tesseract.js（ブラウザ） | テキスト・数値の抽出。混合行列・ヒートマップは数値グリッドを自動解析。それ以外は生テキストを返しユーザーが手動構造化 |
| APIキーあり | Vision LLM | JSON スキーマ付きプロンプトで構造化データを直接取得。Google Cloud Vision API（OCR専用）ではなくマルチモーダル LLM を使用する理由は、単純なテキスト抽出ではなく「スキーマに沿った構造推定」が必要なため |

### ユーザー確認・修正

自動抽出の精度は100%ではないため、確認・修正ステップは**必須**として設計する。
スキップ可能にせず、常に表示する。

## Vision API 設定 UI

```
Vision API 設定（任意）
┌──────────────────────────────────────────────────┐
│ 解析方法  [ Claude | GPT-4o | Gemini | Tesseract ] │
│ API キー  [                                      ] │
└──────────────────────────────────────────────────┘
※ 未設定の場合は自動的に Tesseract.js にフォールバック
```

- キーはブラウザの localStorage に保存する
- APIキー未設定時は Tesseract.js が自動選択される

---

## 図種別の対応状況

| 図種 | キーなし（Tesseract.js） | キーあり（Vision LLM） |
|---|---|---|
| 混合行列 | 数値グリッドを自動解析（精度: 高） | より高精度 |
| ヒートマップ | 数値グリッドを自動解析（精度: 高） | より高精度 |
| 棒グラフ・その他 | 生テキスト返却（手動構造化が必要） | 対応 |
| 折れ線・散布図 | 手動点取り（PointDigitizer）で対応 | 対応 |

> **Note:** 棒グラフのピクセル計測（棒の高さを画素から算出）は未実装。
> Tesseract.js でキーなし時の棒グラフは生テキストのみで、手動での値入力が必要。
