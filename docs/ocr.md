# Phase 6 OCR パイプライン

## 概要

アップロードされた PNG を解析してデータを復元し、編集可能な FigureState に変換する。
OCR だけでは軸・棒・線・色は復元できないため、処理を明確に分離する。

---

## パイプライン

```
PNG アップロード
    ↓
【前処理】Python / Pillow
    - グリッド検出
    - コントラスト調整
    - ノイズ除去
    ↓
【文字抽出】OCR
    ┌─────────────────────┬──────────────────────────────┐
    │ APIキーなし          │ APIキーあり                   │
    │ Tesseract.js         │ Vision API                    │
    │ （ブラウザ）         │ （Google / OpenAI / Claude）  │
    └─────────────────────┴──────────────────────────────┘
    ↓
【図形解析】
    - 軸スケール復元
    - 棒の高さ計測
    - 構造の推定
    ↓
【ユーザー確認・修正】
    - 抽出結果を表示
    - ユーザーが確認・修正
    ↓
FigureState
```

---

## 各ステップの詳細

### 前処理（Python / Pillow）

- グリッド線の検出（混合行列・ヒートマップに有効）
- コントラスト・明度調整（OCR 精度向上のため）
- ノイズ除去

### 文字抽出（OCR）

| 条件 | 処理 | 用途 |
|---|---|---|
| APIキーなし | Tesseract.js（ブラウザ） | ラベル・数値テキストの読み取り |
| APIキーあり | Vision API | テキスト抽出 + 図の構造理解 |

Tesseract.js と pytesseract は同じ Tesseract エンジンのラッパーであり二重処理になるため、
キーなし時は Tesseract.js（ブラウザ）に統一し、pytesseract は使わない。

### 図形解析

OCR が担うのはテキスト抽出のみ。軸・棒・線・色の復元は別処理として分離する。

| 図種 | 解析手法 | 精度 |
|---|---|---|
| 混合行列・ヒートマップ | グリッド検出 + セル値OCR | 高 |
| 棒グラフ | 棒の高さを画素で計測 + 軸スケール復元 | 中 |
| 折れ線・散布図 | 軸スケール復元 + 手動点指定（WebPlotDigitizer方式） | 低〜中 |

### ユーザー確認・修正

自動抽出の精度は100%ではないため、確認・修正ステップは**必須**として設計する。
スキップ可能にせず、常に表示する。

```
Vision API 設定（任意）
┌──────────────────────────────────────────┐
│ プロバイダー  [ Google ▼ / OpenAI / Claude ] │
│ API キー     [                          ] │
└──────────────────────────────────────────┘
```

- 使用状況の表示は行わない（APIキー方式ではプロバイダー側から残量取得が困難なため）
- キーはブラウザの localStorage に保存する

## 図種別の対応状況

| 図種 | キーなし（Tesseract.js + Pillow） | キーあり（Vision API） |
|---|---|---|
| 混合行列 | 高精度で対応 | より高精度 |
| ヒートマップ | 高精度で対応 | より高精度 |
| 棒グラフ | 部分対応（数値は取れるが棒高さは近似） | 対応 |
| 折れ線・散布図 | 手動点指定が必要 | 対応 |
